# المحور الأول — كيف تعمل الآلة؟ من التدريب إلى التوليد

> النسخة العلمية/التدريسية المعتمدة للتصميم الكامل. لا تتضمن معلومات إدارية على الشرائح، وتفصل بين ما يظهر على الشاشة وما يقوله المحاضر.

## الهدف العام
أن يخرج المتدرب بصورة ذهنية واضحة عن موضع النموذج داخل منظومة الذكاء الاصطناعي، وكيف تتحول البيانات إلى تمثيلات رقمية، وما الذي يحدث أثناء التدريب، وما الذي يحدث أثناء التوليد، ولماذا لا تساوي الطلاقة الدقة، وما الفرق بين التدريب والسياق وRAG والأدوات والذاكرة.

## 02 — كيف تعمل الآلة؟
### يظهر على الشاشة
- كيف تعمل الآلة؟
- من التدريب إلى التوليد
- سؤال بصري: ماذا يحدث بين ما يدخل إلى النظام وما يخرج منه؟

### الفكرة الشفهية
قبل الحديث عن هندسة الأوامر يجب أن نعرف بصورة عملية: ما هو النموذج؟ ماذا يدخل إليه؟ ما الفرق بين ما حدث أثناء التدريب وما يحدث عندما نكتب له الآن؟

## 03 — خريطة الرحلة داخل الآلة
### يظهر على الشاشة
المفاهيم → البيانات → التمثيل الرقمي → التدريب → التوليد → القدرات والحدود → الإنسان والعمل → تصحيح المفاهيم → Workshop

### الفكرة الشفهية
هذه ليست أجندة منفصلة، بل مسار واحد داخل النظام: من تعريف الشيء إلى طريقة عمله ثم أثره على العمل البشري.

---

## 04 — AI ليس ChatGPT
### يظهر على الشاشة
لوحة تفاعلية مركزها AI، وحولها:
Classification / Prediction / Detection / Recommendation / Generation / Assistant / Agent / ChatGPT

### الرسالة الأساسية
- ChatGPT تطبيق يستخدم قدرات الذكاء الاصطناعي، لكنه لا يساوي مجال الذكاء الاصطناعي كله.
- Assistant أحد أدوار/أنماط تطبيق الذكاء الاصطناعي، وليس تعريفًا للذكاء الاصطناعي.
- AI Capability ≠ Chat Interface

### المشاهد الفرعية عند النقر
- Classification: عناصر تتحرك إلى فئات.
- Prediction: بيانات حالية تتحول إلى قيمة/نتيجة متوقعة.
- Detection: عنصر أو نمط يبرز داخل مجموعة بيانات.
- Recommendation: خيارات ثم ترتيب/اقتراح.
- Generation: Prompt → Model → Output جديد.
- Assistant: Human ↔ AI في دورة مساعدة.
- Agent: Goal → Plan → Tool → Action → Result.
- ChatGPT: واجهة/تطبيق أمام نموذج وتعليمات وسياق وأدوات؛ لا يساوي AI كله.

---

## 05 — من AI إلى LLM
### يظهر على الشاشة
AI → Machine Learning → Deep Learning → Foundation Models → Large Language Models
ومجال متداخل منفصل جزئيًا لـGenerative AI: Text / Image / Audio / Video / Code.

### الرسائل الأساسية
- Artificial Intelligence هو المظلة الأوسع.
- Machine Learning أحد المسارات داخل AI.
- Deep Learning أسرة من تقنيات ML تعتمد شبكات عميقة.
- Foundation Model نموذج واسع التدريب يمكن تكييفه لمهام متعددة.
- LLM نوع من Foundation Models يركز أساسًا على اللغة.
- Generative AI أوسع من LLM؛ ليس كل توليد لغويًا.
- Foundation Model ≠ LLM دائمًا.
- Generative AI ≠ LLM.

---

## 06 — Algorithm ≠ AI
### يظهر على الشاشة
Algorithm: Input → Steps / Rules → Output
وفي المقابل AI System: Data + Algorithms + Model + Software + Tools.
ثم: Model ≠ Application ≠ Agent

### الرسالة الأساسية
الخوارزمية طريقة أو خطوات منظمة لتنفيذ مهمة أو حل مشكلة. قد تكون جزءًا من نظام ذكاء اصطناعي، لكنها ليست مرادفًا للذكاء الاصطناعي.

---

## 07 — البيانات: ماذا يدخل إلى المنظومة؟
### يظهر على الشاشة
Text / PDF / Table / Image / Audio / Database
Structured ↔ Unstructured

### أمثلة قانونية
- Structured: جدول قضايا، أعمدة، تواريخ، أرقام دعاوى، حالات.
- Unstructured: أحكام، عقود، مذكرات، PDFs، صور، تسجيلات.

### الرسالة الأساسية
قبل أن يعمل النظام على المعرفة المهنية، يجب أن توجد بيانات قابلة للإدخال والتنظيم والمعالجة.

---

## 08 — كيف يرى الإنسان؟ وكيف يرى الكمبيوتر؟
### يظهر على الشاشة
Human View: صورة + كلمات + معنى
Machine View: تمثيلات رقمية قابلة للحساب

### الرسالة الأساسية
الكمبيوتر لا «يرى» الصورة أو «يقرأ» النص بالطريقة البشرية نفسها؛ بل يحتاج إلى تحويل المدخلات إلى تمثيلات رقمية يمكن إجراء عمليات حسابية عليها.

---

## 09 — كيف تتحول الصورة إلى بيانات؟
### يظهر على الشاشة
Image → Pixels → Numeric Values → Patterns / Features

### الشرح
- الصورة الرقمية شبكة من Pixels.
- لكل Pixel قيم رقمية تمثل اللون أو الشدة وفق طريقة التمثيل.
- عند المعالجة تتعامل الأنظمة مع هذه القيم والبنى الناتجة عنها.
- تتعلم النماذج البصرية أنماطًا وعلاقات أكثر تعقيدًا من القيم الخام.

### الرسالة الأساسية
الصورة داخل الحاسب = قيم رقمية منظمة + موقع/بنية + معالجة حسابية.

---

## 10 — كيف تتحول الكتابة إلى بيانات؟
### يظهر على الشاشة
Text → Tokens → Token IDs → Numerical Representation

### الشرح
- النص يُجزأ وفق Tokenizer إلى Tokens؛ وقد تكون كلمة أو جزءًا من كلمة أو رمزًا أو علامة بحسب اللغة والنموذج.
- ترتبط الوحدات بمعرفات عددية.
- داخل النموذج تستخدم تمثيلات عددية تمكن العمليات الحسابية والتعلم من العلاقات.

### الرسالة الأساسية
النموذج لا يتعامل مع «المعنى المكتوب» ككيان مجرد؛ بل مع تمثيلات رقمية للنص.

---

## 11 — حيث يلتقي النص والصورة
### يظهر على الشاشة
Image path → Digital Representation
Text path → Digital Representation

### الرسالة الأساسية
طرق الترميز والمعالجة تختلف بين النص والصورة، لكن القاسم المشترك أن الحاسب يحتاج إلى تمثيلات رقمية قابلة للحساب. لا نقول إن النص والصورة «يتحولان إلى الشيء نفسه» حرفيًا.

---

## 12 — من يعمل على البيانات والمنظومة؟
### يظهر على الشاشة كـPipeline
Raw Data → Data System → Model → AI Application
وفوقها أدوار:
- Data Engineer
- Data Analyst
- Data Scientist
- ML Engineer
- AI Engineer

### الشرح المختصر
- Data Engineer: يجعل البيانات متاحة ومنظمة وموثوقة وقابلة للتدفق.
- Data Analyst: يستخرج أنماطًا ومؤشرات وتقارير من البيانات.
- Data Scientist: يستكشف البيانات والنمذجة والتجارب والاستنتاج.
- ML Engineer: يبني/يدرّب/ينشر/يقيّم نماذج تعلم الآلة.
- AI Engineer: يركب النموذج مع Prompt + Context + Knowledge/RAG + Tools + Evaluation داخل تطبيق قابل للاستخدام.

### القيد العلمي
المسميات والحدود بين الأدوار تتداخل باختلاف المؤسسة والمشروع.

---

## 13 — كيف تتعلم الآلة؟
### يظهر على الشاشة
Data / Representation → Model → Prediction → Compare → Error → Weight Adjustment → Repeat → Trained Model

### الرسالة الأساسية
التدريب عملية تكرارية يتغير خلالها النموذج استنادًا إلى الخطأ/إشارة التعلم. الفكرة التعليمية المركزية: **التدريب يغير الأوزان/المعلمات**.

### ما لا نعرضه
لا معادلات Backpropagation، لا Gradient Descent رياضي، لا تفاصيل Q/K/V.

---

## 14 — Tokens / Representation / Parameters & Weights
### يظهر على الشاشة
Token → ID → Representation
ثم شبكة Connections تحمل قيمًا رقمية تتغير أثناء التدريب.

### الرسائل الأساسية
- Parameters هي قيم يتعلمها/يضبطها التدريب داخل النموذج.
- Weights جزء أساسي من هذه المعلمات وتؤثر في انتقال الإشارات والعلاقات.
- Model ≠ Document Database.
- الأوزان ليست مستندات تدريب محفوظة يمكن فتحها مثل ملفات قاعدة بيانات.
- لا نقول إن الحفظ لا يحدث مطلقًا؛ يمكن أن تظهر صور من memorization في بعض الحالات.

---

## 15 — ماذا تقصد بـ«علّمت النموذج»؟
### يظهر على الشاشة
Training / Fine-tuning / Prompting / Context / RAG / Memory / Tool Use
وتذهب كل واحدة إلى موقع مختلف في Architecture.

### الفروق
- Training: تعلم أساسي يغير أوزان النموذج.
- Fine-tuning: تدريب إضافي يكيف نموذجًا قائمًا؛ يغير الأوزان.
- Prompting: تعليمات وقت الاستخدام؛ لا يعني تدريبًا جديدًا.
- Context: معلومات متاحة للنموذج أثناء المهمة الحالية.
- RAG: استرجاع معلومات خارجية ذات صلة ثم إضافتها إلى السياق.
- Memory: حالة/معلومات محفوظة بواسطة التطبيق وفق تصميمه، وليست مرادفًا للتدريب.
- Tool Use: استدعاء قدرة خارجية مثل Search أو Database أو Calculator أو API/ملفات.

### الرسالة الأساسية
ليس كل ما يجعل النظام يعرف شيئًا أو يفعله هو Training.

---

## 16 — انتهى التدريب… والآن كتبت سؤالًا
### يظهر على الشاشة
Prompt → Tokens → Context → Model → Probability Distribution → Next Token → Add to Context → Repeat → Response

### الرسائل الأساسية
- التدريب تم مسبقًا.
- سؤال المستخدم العادي لا يعيد تدريب النموذج.
- التوليد اللغوي يبني الاستجابة تدريجيًا عبر اختيار/توليد Tokens تالية وفق توزيع احتمالي وسياق حالي.
- لا نختزل النموذج في عبارة «Autocomplete فقط»؛ Next-token prediction آلية توليد أساسية داخل نظام أكبر.
- Generation ≠ Retraining.

---

## 17 — Context Window: ماذا يرى النموذج الآن؟
### يظهر على الشاشة
داخل نافذة السياق:
System Instructions / User Prompt / Conversation / Documents / Retrieved Knowledge / Tool Results
وخارجها معلومات غير متاحة لهذه المهمة.

### الرسائل الأساسية
- Context = ما هو متاح للنموذج أثناء تنفيذ المهمة.
- Context ≠ Training.
- Context ≠ Permanent Memory.
- File Upload ≠ Fine-tuning.
- Prompt يوجّه؛ Context يزوّد.

---

## 18 — ماذا يستطيع AI أن يفعل؟
### يظهر على الشاشة حول ملف قضية واحد
Extract / Classify / Summarize / Compare / Retrieve / Generate / Recommend / Use Tools

### أمثلة قانونية
- استخراج الأطراف والتواريخ والمبالغ.
- تصنيف القضايا/العقود.
- تلخيص حكم.
- مقارنة نسختين من عقد.
- استرجاع حكم ذي صلة.
- توليد مسودة مذكرة.
- ترتيب بدائل.
- البحث في قاعدة بيانات أو إجراء حساب.

### الرسالة الأساسية
AI Capability ≠ Chat Interface.

---

## 19 — لماذا يخطئ وهو يبدو مقنعًا؟
### يظهر على الشاشة
مرجع قانوني افتراضي/وهمي → SOURCE? → NOT FOUND
ثم:
Fluency ≠ Accuracy
Confidence ≠ Evidence
Generated ≠ Verified

### الرسالة الأساسية
جودة الصياغة لا تثبت صحة الواقعة أو المرجع. في العمل القانوني تكون قيمة الدليل والتحقق أعلى من انطباع الثقة والطلاقة.

---

## 20 — ماذا نعني بالاستدلال؟
### يظهر على الشاشة
Simple: Input → Output
Complex: Input → Interpret → Compare → Check → Revise → Output

### الرسالة الأساسية
يمكن للنماذج معالجة مهام متعددة الخطوات، لكن نجاحها في ذلك لا يعني أنها «عقل بشري» أو أنها واعية. نتحدث هنا عن سلوك/معالجة متعددة المراحل، لا عن إثبات حالة عقلية بشرية.

---

## 21 — كيف يعيد AI تشكيل العمل؟
### يظهر على الشاشة
Job → Tasks
ثم توزيع المهام إلى:
Human / Human + AI / AI-Assisted / Delegatable / Human Review Required

### الرسالة الأساسية
الأدق من عبارة «AI سيستبدل الوظائف» أن نقول: AI يعيد تشكيل المهام؛ المهام تعيد تشكيل المهارات؛ ومع الوقت قد تعيد هذه التحولات تشكيل الوظائف.

## 22 — المهارات التي ترتفع قيمتها
### يظهر على الشاشة
مساران يلتقيان:
AI/Digital: AI Literacy / Data Literacy / Prompting / Context Design / Workflow Design / Tool Use
Human/Professional: Domain Expertise / Judgment / Critical Thinking / Verification / Responsibility / Decision-making

### الرسالة الأساسية
القيمة المهنية تنتقل نحو القدرة على تحديد المهمة، توجيه النظام، تزويده بالمعلومات، تنظيم سير العمل، التفويض بدرجات مناسبة، ثم التحقق والقرار والمسؤولية.

## 23 — الصورة الكاملة
### يظهر على الشاشة كـArchitecture واحدة
Training → Model Weights
Fine-tuning → Model Weights
Prompting → Instructions
Context → Working Context
RAG → Knowledge Base → Retrieve → Context
Memory → Stored State / Information
Tool Use → External Capability

### الرسالة الأساسية
هذه عمليات مختلفة داخل النظام. **إعطاء الآلة معلومات ≠ تدريبها**.

## 24 — خلاصة المحور
### يظهر على الشاشة
- البيانات تغذي المنظومة.
- التدريب يشكل النموذج.
- السياق يحدد ما هو متاح أثناء المهمة.
- التوليد يبني المخرج تدريجيًا.
- الطلاقة ليست دليلًا على الحقيقة.

ثم السؤال:
**هل دربت الآلة فعلًا؟**

## 25 — Workshop 01: هل دربت الآلة فعلًا؟
### الحالات
A — رفعت مجموعة أحكام وطلبت تحليلها. → Context / File use
B — استخدمت Dataset لتدريب إضافي على نموذج قائم. → Fine-tuning
C — كتبت تعليمات مفصلة تحدد المهمة والقيود والمخرج. → Prompting
D — النظام يسترجع أحكامًا ذات صلة من قاعدة معرفة ويضيفها للسياق. → RAG
E — النظام يستخدم Search أو Calculator أو Database أثناء التنفيذ. → Tool Use

### آلية التفاعل
تظهر الحالات دون الحل. يجيب الجمهور، ثم يكشف المحاضر الإجابات أو يسحب كل حالة إلى موقعها الصحيح.

### الرسالة الختامية
**إعطاء الآلة معلومات ≠ تدريبها**

### الانتقال إلى المحور الثاني
إذا فهمنا كيف تعمل الآلة، يصبح السؤال التالي: **كيف نصوغ لها ما نريد بدقة؟**
→ هندسة الأوامر Prompt Engineering.
