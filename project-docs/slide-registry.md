# سجل الشرائح التحريري

## من مخاطبة الآلة إلى تفويضها

هذا السجل هو مرجع التعديل المعتمد للمحتوى والهوية والحركة. لا يُغيَّر رقم شريحة أو عنوانها إلا بتعديل صريح هنا. يظهر المصطلح الإنجليزي أولًا، ثم يتحول بأسلوب رقمي إلى المقابل العربي المستقر على الشاشة. لا تستخدم الواجهة لفظ «فصل»؛ التسمية المعتمدة هي «المحور الأول» إلى «المحور الخامس».

## الافتتاح

### S01
- **المحور:** الافتتاح
- **العنوان:** من مخاطبة الآلة إلى تفويضها
- **المصطلح:** `Prompt → Context → Workflow → Agent` → `الأمر → السياق → سير العمل → الوكيل`
- **النص الظاهر:** «من مخاطبة الآلة» ثم «إلى تفويضها»؛ «من هندسة الأوامر إلى هندسة الوكلاء».
- **التمثيل البصري:** مؤشر كتابة داخل مربع أمر، ومسار مضيء يتسع إلى منظومة.
- **الحركة/التفاعل:** مشهد افتتاحي ذاتي 8–10 ثوانٍ؛ الكاميرا تتراجع من المؤشر إلى المسار، ثم يبقى المشهد تحت تحكم المحاضر.

### S02
- **المحور:** الافتتاح
- **العنوان:** ماذا يحدث بعد أن تضغط Enter؟
- **المصطلح:** `Input → Output` → `مدخل → مخرج`؛ `Tokens / Representations / Model / Context / Generation` → `رموز / تمثيلات / نموذج / سياق / توليد`.
- **النص الظاهر:** «ماذا يحدث بعد أن تضغط Enter؟» ثم «مدخل → ؟ → مخرج».
- **التمثيل البصري:** مستخدم، صندوق أسود، وإجابة تظهر في الجهة المقابلة.
- **الحركة/التفاعل:** تدخل عبارة «حلل هذا العقد» إلى الصندوق؛ النقر عليه يفتح طبقات النظام واحدةً واحدة.

### S03
- **المحور:** الافتتاح
- **العنوان:** تطور واجهة الإنسان مع الآلة
- **المصطلح:** `Command → Click → Search → Prompt → Delegate` → `أمر → نقر → بحث → توجيه → تفويض`.
- **النص الظاهر:** خط زمني قصير، وفوق كل محطة فعل واحد: اكتب، انقر، ابحث، وجّه، فوّض.
- **التمثيل البصري:** Timeline تقني بأيقونات طرفية غير زخرفية.
- **الحركة/التفاعل:** سحب مؤشر الخط الزمني ذهابًا وعودة؛ تتغير الواجهة ومعها مقدار ما يُفوَّض للآلة.

### S04
- **المحور:** الافتتاح
- **العنوان:** خريطة المحاضرة
- **المصطلح:** `Governance` → `حوكمة التفويض`.
- **النص الظاهر:** افهم، وجّه، زوّد، نظّم، فوّض، راقب؛ ومع كل محطة سؤالها المختصر.
- **التمثيل البصري:** خمس محطات متصلة داخل خريطة واحدة، لا بطاقات منفصلة.
- **الحركة/التفاعل:** بناء المحطات بالتتابع؛ النقر يذهب إلى المحور المختار، وزر «الخريطة» يعيد إليها.

## المحور الأول — كيف تعمل الآلة؟

### S05
- **المحور:** المحور الأول — كيف تعمل الآلة؟
- **العنوان:** قبل النموذج توجد البيانات
- **المصطلح:** `Data` → `البيانات`.
- **النص الظاهر:** «الذكاء الاصطناعي لا يبدأ بالنموذج. يبدأ بالبيانات.»
- **التمثيل البصري:** نص وصورة وصوت وفيديو وبرمجيات ووثائق تتجه إلى مركز واحد.
- **الحركة/التفاعل:** يتحول كل مدخل إلى نبضات رقمية؛ النقر يعرض مثالًا سريعًا لما يصير إليه النص أو الصورة.

### S06
- **المحور:** المحور الأول — كيف تعمل الآلة؟
- **العنوان:** الذكاء الاصطناعي منظومة
- **المصطلح:** `Data → Process → Train → Model → Inference → Output` → `بيانات → معالجة → تدريب → نموذج → استدلال → مخرج`.
- **النص الظاهر:** خط المنظومة كاملًا، مع تمييز الفرق بين التدريب والاستخدام.
- **التمثيل البصري:** Pipeline يمتد بعرض الشاشة؛ النموذج جسم ثابت والأمر يدخل بعده.
- **الحركة/التفاعل:** مفتاح «تدريب / استخدام» يعزل الجزء المقصود ويعيد تشغيل تدفقه.

### S07
- **المحور:** المحور الأول — كيف تعمل الآلة؟
- **العنوان:** كيف ترى الآلة النص والصورة؟
- **المصطلح:** `Representation` → `تمثيل رقمي`.
- **النص الظاهر:** «الإنسان يرى معنى. الحاسوب يحتاج تمثيلًا.»
- **التمثيل البصري:** جهة إنسانية فيها عقد وكلمة «تحكيم»، وجهة رقمية فيها نقاط ومتجهات.
- **الحركة/التفاعل:** يسحب المحاضر كلمة أو صورة أو صوتًا إلى «تمثيل الآلة» فتتحول أمام الجمهور.

### S08
- **المحور:** المحور الأول — كيف تعمل الآلة؟
- **العنوان:** من النص إلى التمثيل
- **المصطلح:** `Tokens → Embeddings → Contextual Representations` → `وحدات رمزية → تمثيلات متجهية → تمثيلات سياقية`.
- **النص الظاهر:** «فسخ العقد بسبب التأخير» ثم مسار التحول في ثلاث مراحل.
- **التمثيل البصري:** الجملة تتجزأ، ثم تصير نقاطًا في فضاء بصري متحرك.
- **الحركة/التفاعل:** سحب «العقد» نحو «فسخ» يظهر صلةً ومسافةً تقريبية؛ التمرير يوضح المعنى في سطر واحد.

### S09
- **المحور:** المحور الأول — كيف تعمل الآلة؟
- **العنوان:** السياق يغيّر المعنى
- **المصطلح:** `Context` → `السياق`.
- **النص الظاهر:** «عين»؛ «الكلمة لم تتغير. السياق تغيّر.»
- **التمثيل البصري:** الكلمة في المركز وثلاث بيئات: عين الإنسان، عين الماء، عين على المشروع.
- **الحركة/التفاعل:** يسحب المحاضر الكلمة إلى كل جملة فتتغير هيئة تمثيلها ولونه.

### S10
- **المحور:** المحور الأول — كيف تعمل الآلة؟
- **العنوان:** ماذا يعني التدريب؟
- **المصطلح:** `Predict → Compare → Error → Adjust → Repeat` → `يتوقع → يقارن → يخطئ → يعدّل → يكرر`.
- **النص الظاهر:** دورة التدريب في خمس كلمات.
- **التمثيل البصري:** حلقة دائرية حول جملة ناقصة: «العقد ____ نافذًا».
- **الحركة/التفاعل:** زر «دورة جديدة» يشغّل توقعًا ومقارنة وتعديلًا مرئيًا بسيطًا داخل الشبكة.

### S11
- **المحور:** المحور الأول — كيف تعمل الآلة؟
- **العنوان:** المعاملات والأوزان
- **المصطلح:** `Parameters & Weights` → `المعاملات والأوزان`.
- **النص الظاهر:** «المعاملات ليست مكتبة معلومات.»
- **التمثيل البصري:** مكتبة تظهر ثم تُشطب وتتحول إلى شبكة علاقات.
- **الحركة/التفاعل:** منزلق «قليل ← مليارات» يزيد كثافة الوصلات؛ النقر على معامل يضيء علاقة واحدة ثم الشبكة كلها.

### S12
- **المحور:** المحور الأول — كيف تعمل الآلة؟
- **العنوان:** الأمر ليس تدريبًا
- **المصطلح:** `Prompting / RAG / Fine-tuning / Training` → `إعطاء الأمر / التوليد المعزّز بالاسترجاع / الضبط الدقيق / التدريب`.
- **النص الظاهر:** أربع عمليات حول نموذج واحد؛ لا جدول مقارنة.
- **التمثيل البصري:** النموذج في المركز ومناطق إدخال مختلفة حوله.
- **الحركة/التفاعل:** يسحب المحاضر كل عملية إلى النموذج؛ فتدخل تعليمات أو وثيقة أو يظهر تعديل محدود أو تدريب واسع بحسب الاختيار.

### S13
- **المحور:** المحور الأول — كيف تعمل الآلة؟
- **العنوان:** التوليد وحدود السياق
- **المصطلح:** `Generation / Hallucination / Context Window` → `التوليد / الهلوسة / نافذة السياق`.
- **النص الظاهر:** «الكلمة التالية، ثم التالية»؛ «المحتمل لا يساوي الصحيح».
- **التمثيل البصري:** إجابة تتولد وحدةً بوحدة، وتحذير بجوار مثال قانوني افتراضي، ونافذة سياق تتلقى مدخلات.
- **الحركة/التفاعل:** يسحب المحاضر تعليمات وملفًا ونتيجة بحث داخل النافذة أو خارجها؛ يتبدل اتساق المخرج بصريًا.

### S14
- **المحور:** المحور الأول — كيف تعمل الآلة؟
- **العنوان:** ورشة: افتح الصندوق الأسود
- **المصطلح:** `Input / Representation / Context / Generation / Verification` → `المدخل / التمثيل / السياق / التوليد / التحقق`.
- **النص الظاهر:** «حلل هذا العقد وحدد أهم المخاطر.»
- **التمثيل البصري:** خمس مناطق فارغة وبطاقات: ملف عقد، تعليمات، وحدات رمزية، مصدر قانوني، إجابة، فحص استشهاد.
- **الحركة/التفاعل:** سحب وإفلات البطاقات في مواضعها؛ عند اكتمالها تظهر: «قبل أن تحسن الأمر، افهم الآلة التي ستنفذه.»

## المحور الثاني — هندسة الأوامر

### S15
- **المحور:** المحور الثاني — هندسة الأوامر
- **العنوان:** الأمر ليس سؤالًا
- **المصطلح:** `Prompt Engineering` → `هندسة الأوامر`؛ `Instruction Architecture` → `بنية التعليمات`.
- **النص الظاهر:** «الأمر بنية تعليمات، لا صياغة عابرة.»
- **التمثيل البصري:** «راجع العقد» في المركز يتفكك إلى خانات هدف وسياق ومهمة وقيود ومخرج وجودة.
- **الحركة/التفاعل:** Build هادئ للخانات؛ تظل مفتوحة لمداخلات المحاضر.

### S16
- **المحور:** المحور الثاني — هندسة الأوامر
- **العنوان:** لماذا تفشل الأوامر الغامضة؟
- **المصطلح:** `Guessing Space` → `مساحة التخمين`.
- **النص الظاهر:** «اكتب مذكرة عن بطلان حكم التحكيم.» ثم أسئلة النقص الأساسية.
- **التمثيل البصري:** الجملة في الوسط، وحولها فروع: الدولة، الحكم، السبب، المحكمة، المصدر، الغرض.
- **الحركة/التفاعل:** النقر على كل معلومة ناقصة يخفض مقياس مساحة التخمين.

### S17
- **المحور:** المحور الثاني — هندسة الأوامر
- **العنوان:** الهدف والسياق والمهمة
- **المصطلح:** `Goal + Context + Task` → `الهدف + السياق + المهمة`.
- **النص الظاهر:** «لماذا؟ ماذا يحتاج أن يعرف؟ ماذا يفعل؟»
- **التمثيل البصري:** ثلاث دوائر تدخل إلى منشئ الأوامر.
- **الحركة/التفاعل:** يسحب المحاضر بطاقات صحيحة؛ فيتكون أمر تفاوضي متماسك أمام الحضور.

### S18
- **المحور:** المحور الثاني — هندسة الأوامر
- **العنوان:** القيود والمخرج ومعيار الجودة
- **المصطلح:** `Constraints + Output + Quality` → `القيود + المخرج + معيار الجودة`.
- **النص الظاهر:** «ما الحدود؟ كيف تكون النتيجة؟ متى نعدها جيدة؟»
- **التمثيل البصري:** منشئ الأوامر نفسه وقد أضيفت له ثلاث خانات جديدة.
- **الحركة/التفاعل:** بطاقات «لا تفترض»، «جدول مخاطر»، «استشهد بالنص» تُسحب إلى الخانات؛ يتحول الناتج من فقرة إلى جدول.

### S19
- **المحور:** المحور الثاني — هندسة الأوامر
- **العنوان:** الدور الوظيفي لا المديح
- **المصطلح:** `Role Prompting` → `تحديد الدور الوظيفي`.
- **النص الظاهر:** «أنت أفضل محامٍ في العالم» ثم «تعمل كمراجع عقود يمثل المشتري…»
- **التمثيل البصري:** مقارنة قبل/بعد في لوحتين.
- **الحركة/التفاعل:** مفتاح «دور فضفاض / دور وظيفي» يبدل زاوية التحليل واللغة المتوقعة.

### S20
- **المحور:** المحور الثاني — هندسة الأوامر
- **العنوان:** الأفعال الدقيقة
- **المصطلح:** `Task Decomposer` → `مفكك المهمة`.
- **النص الظاهر:** «راجع» تتحول إلى «استخرج → صنّف → قارن → قيّم → اقترح».
- **التمثيل البصري:** آلة صغيرة تفكك الفعل العام إلى خطوات قابلة للملاحظة.
- **الحركة/التفاعل:** سحب «راجع» إلى المفكك؛ تخرج الأفعال تباعًا ويمكن إعادة ترتيبها.

### S21
- **المحور:** المحور الثاني — هندسة الأوامر
- **العنوان:** المثال يصنع النمط
- **المصطلح:** `Few-Shot Prompting` → `التوجيه بالأمثلة القليلة`.
- **النص الظاهر:** «مثال → نمط → مدخل جديد».
- **التمثيل البصري:** مثالان لتصنيف بند عقد وبطاقة ثالثة تنتظر التصنيف.
- **الحركة/التفاعل:** تسحب البطاقة الثالثة إلى النموذج فيظهر التصنيف على النمط نفسه.

### S22
- **المحور:** المحور الثاني — هندسة الأوامر
- **العنوان:** فكّك المهمة الكبيرة
- **المصطلح:** `Decomposition` → `تفكيك المهمة`.
- **النص الظاهر:** «المهمة الكبيرة لا تحتاج أمرًا أكبر.»
- **التمثيل البصري:** كتلة «أعد مذكرة قانونية كاملة» تتفرع إلى وقائع ومسائل وقانون وتحليل ومسودة ومراجعة.
- **الحركة/التفاعل:** سحب الكتلة إلى منطقة التفكيك؛ تبقى الأجزاء قابلة للترتيب تمهيدًا لسير العمل.

### S23
- **المحور:** المحور الثاني — هندسة الأوامر
- **العنوان:** صحّح الأمر قبل أن تكرره
- **المصطلح:** `Prompt Debugging` → `تشخيص الأمر`.
- **النص الظاهر:** «النتيجة سيئة؟ شخّص السبب.» ثم «لا تسأل: هل أنت متأكد؟ اسأل: ما الدليل؟»
- **التمثيل البصري:** لوحة تشخيص تضم غموض الهدف ونقص السياق واتساع المهمة وغياب المخرج والدليل وتعارض التعليمات.
- **الحركة/التفاعل:** يختار المحاضر العيب فتظهر توصية تحريرية واحدة مناسبة.

### S24
- **المحور:** المحور الثاني — هندسة الأوامر
- **العنوان:** ورشة: أصلح الأمر
- **المصطلح:** `Jurisdiction / Issue / Sources / Verification` → `الاختصاص / المسألة / المصادر / التحقق`.
- **النص الظاهر:** «ابحث عن موقف القضاء من بطلان حكم التحكيم.»
- **التمثيل البصري:** أمر في الوسط وسبع كتل محيطة لبناء أمر جديد.
- **الحركة/التفاعل:** Drag & Drop للولاية والمسألة والفترة والمصادر والقضايا والمخرج والتحقق؛ تظهر صياغة نهائية قابلة للنقاش.

## المحور الثالث — هندسة السياق

### S25
- **المحور:** المحور الثالث — هندسة السياق
- **العنوان:** أمر ممتاز وسياق خاطئ
- **المصطلح:** `Perfect Prompt + Wrong Context = Wrong Result` → `أمر ممتاز + سياق خاطئ = نتيجة خاطئة`.
- **النص الظاهر:** المعادلة وحدها.
- **التمثيل البصري:** أمر أخضر متصل بملف قديم أو غير ذي صلة، ونتيجة واثقة محذَّرة.
- **الحركة/التفاعل:** يتغير مصدر الملف فيتبدل مسار الثقة؛ لا يحتاج نصًا إضافيًا.

### S26
- **المحور:** المحور الثالث — هندسة السياق
- **العنوان:** كيف أسأل؟ وماذا يحتاج الآن؟
- **المصطلح:** `Prompt Engineering vs Context Engineering` → `هندسة الأوامر مقابل هندسة السياق`.
- **النص الظاهر:** «كيف أسأل؟» / «ماذا يحتاج النموذج الآن؟»
- **التمثيل البصري:** شاشة منقسمة؛ التعليمات في جانب والملفات والذاكرة والبحث والأدوات والحالة في الجانب الآخر.
- **الحركة/التفاعل:** منزلق يوازن بين الجانبين ويبيّن أن الأمر جزء من السياق وليس كله.

### S27
- **المحور:** المحور الثالث — هندسة السياق
- **العنوان:** مما يتكون السياق؟
- **المصطلح:** `Instructions / Files / Retrieved Knowledge / Memory / Tool Results / State` → `تعليمات / ملفات / معرفة مسترجعة / ذاكرة / نتائج أدوات / حالة العمل`.
- **النص الظاهر:** طبقات السياق حول نواة النموذج.
- **التمثيل البصري:** نافذة سياق مركزية وسبع طبقات تدخلها.
- **الحركة/التفاعل:** يمكن تعطيل طبقة بالنقر وملاحظة الأثر على الإجابة النموذجية.

### S28
- **المحور:** المحور الثالث — هندسة السياق
- **العنوان:** الأكثر ليس الأفضل
- **المصطلح:** `Noise / Relevance` → `ضوضاء / صلة`.
- **النص الظاهر:** «أكثر ≠ أفضل».
- **التمثيل البصري:** نافذة سياق و30 وثيقة على جانبها.
- **الحركة/التفاعل:** سحب جميع الوثائق يرفع الضوضاء؛ إعادة التجربة بثلاث وثائق مناسبة ترفع الصلة.

### S29
- **المحور:** المحور الثالث — هندسة السياق
- **العنوان:** ميزانية السياق

- **التمثيل البصري:** أربعة متحكمات متصلة بنتيجة واحدة.
- **الحركة/التفاعل:** تحريك أي منزلق يغير القيمة؛ خفض الحوكمة أو السياق يخفض النتيجة بوضوح.

### S58
- **المحور:** الختام — الرقابة على التفويض
- **العنوان:** السؤال الجديد
- **المصطلح:** `Permissions / Verification / Stop Conditions` → `الصلاحيات / التحقق / شروط التوقف`.
- **النص الظاهر:** «كيف أجعل الذكاء الاصطناعي يجيب أفضل؟» ثم «ما الذي أفوضه؟ بأي صلاحيات؟ كيف أتحقق؟ متى يتوقف؟»
- **التمثيل البصري:** السؤال الأول يتراجع، والأسئلة الجديدة تصير دوائر تحيط بالوكيل.
- **الحركة/التفاعل:** Reveal متتابع في وقت المحاضر؛ كل سؤال يضيء جزءًا من نظام الحوكمة.

### S59
- **المحور:** الختام — الرقابة على التفويض
- **العنوان:** المستقبل في النظم الأفضل
- **المصطلح:** `The future is not better prompts. It is better systems.` → `المستقبل ليس أوامر أفضل، بل نظم أفضل`.
- **النص الظاهر:** الجملة النهائية وحدها.
- **التمثيل البصري:** أمر صغير تتجمع حوله طبقات السياق والأدوات والذاكرة وسير العمل والتقييم والرقابة البشرية حتى يصير بنية نظام.
- **الحركة/التفاعل:** مشهد هادئ يعيد صدى الافتتاح؛ يظل مستمرًا 5–7 ثوانٍ أو أكثر وفق شرح المحاضر.

### S60
- **المحور:** الختام — الرقابة على التفويض
- **العنوان:** فوّض التنفيذ، لا المسؤولية
- **المصطلح:** `Human Oversight` → `الرقابة البشرية`.
- **النص الظاهر:** «فوّض التنفيذ.» ثم «ولا تفوّض المسؤولية.»
- **التمثيل البصري:** وكيل يعمل داخل دائرة صلاحيات، وخارجها حلقة رقابة بشرية وخريطة الرحلة بخفوت.
- **الحركة/التفاعل:** تتوقف الحركة عند «المسؤولية» ثم تستقر؛ يظهر اسم المحاضر وأكاديمية العدالة قبل الإظلام النهائي.
