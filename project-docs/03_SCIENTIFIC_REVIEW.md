# 03 — المراجعة العلمية والمصطلحية

## حالة الوثيقة

`STATUS: DONE — REVIEW REQUIRED FOR TIME-SENSITIVE EXAMPLES`

**المدخلات المقروءة:** وثيقة المشروع الحاكمة، الـCinematic Storyboard، وسجل الشرائح `S01–S60`.

**قاعدة العمل:** العرض تعليمي وتطبيقي؛ لذلك يشرح الفروق التشغيلية من غير ادعاء وصف كامل للبنية الداخلية لأي منتج بعينه. العربية هي اللغة النهائية على الشاشة، والإنجليزية إشارة مصطلحية متبادلة في المكوّن الثنائي اللغة.

## ضوابط عامة ملزمة

1. لا يساوي الذكاء الاصطناعي منتجًا محددًا، ولا يساوي النموذج تطبيقًا أو وكيلًا.
2. استخدم «قد» و«يعتمد على» عند وصف المخرجات والقدرات؛ لا تستخدم «يفهم» أو «يعرف» بوصفهما إثباتًا لوعي أو يقين.
3. «التوليد» توقع متتابع لوحدات رمزية في ضوء المدخلات والسياق؛ ليس استرجاعًا مضمونًا لوقائع صحيحة.
4. «الهلوسة» تعني مخرجًا غير مسند أو غير صحيح أو غير قابل للتحقق، لا كذبًا أو قصدًا من النموذج.
5. الاسترجاع المعزز بالتوليد (RAG) يزوّد السياق بمادة مسترجعة؛ لا يضمن أن المادة صحيحة أو كاملة أو أن المخرج ملتزم بها. التحقق يبقى خطوة مستقلة.
6. الضبط الدقيق (Fine-tuning) يغيّر سلوك النموذج عبر تدريب إضافي على بيانات؛ أما الأمر والسياق والاسترجاع فلا تغيّر أوزان النموذج أثناء الاستخدام المعتاد.
7. الذاكرة ليست مفهومًا واحدًا: فرّق، عند الحاجة، بين سياق الجلسة، وحالة العمل، وذاكرة محفوظة خارجية. لا تفترض أن كل نظام يحتفظ بالمحادثات أو يتعلم منها تلقائيًا.
8. الوكيل نظام موجّه بهدف قد يختار أفعالًا وأدوات ضمن حدود معرّفة؛ لا توجد عتبة موحّدة متفق عليها تجعل كل سير عمل «وكيلًا».
9. الاستقلالية ليست قيمة بذاتها؛ تُعرض دائمًا مع الصلاحيات، شروط التوقف، التصعيد، الموافقة البشرية، والسجل القابل للتدقيق.
10. الأمثلة القانونية تعليمية وافتراضية، ولا تمثل فتوى أو حكمًا قضائيًا أو قاعدة تشريعية ما لم يضاف مصدر محدد ومراجع حديثًا.

## مراجعة الشرائح بحسب النطاق

| النطاق | الحالة | الضبط العلمي قبل التنفيذ |
|---|---|---|
| S01–S04 | معتمد بضوابط | المسار `Prompt → Context → Workflow → Agent` خريطة تعليمية لتزايد التعقيد، لا تسلسل تاريخي حتمي ولا وصف إلزامي لكل نظام. في S02 تُعرض الطبقات بوصفها تبسيطًا؛ ليست كل النماذج أو التطبيقات تعمل بالمكوّنات نفسها أو بالترتيب نفسه. |
| S05–S06 | معتمد | البيانات جزء أساسي من منظومة الذكاء الاصطناعي، لكن لا تقل إن كل نظام يبدأ بالتدريب أو إن جميع البيانات متاحة للمستخدم. فرّق بصريًا بين التدريب المسبق/الإضافي وبين الاستدلال أثناء الاستخدام. |
| S07–S09 | معتمد بضوابط | النص والصورة والصوت تُحوّل إلى تمثيلات قابلة للحساب؛ لا توحِ بأن النقاط المعروضة هي «المعنى» نفسه. `Embedding` تمثيل متجهي، و`Contextual Representation` تمثيل يتأثر بالمحيط؛ مثال «عين» تعليمي لا يثبت فهمًا بشريًا. |
| S10–S11 | معتمد | دورة التدريب: بيانات → توقع → مقارنة بخطأ/هدف → تحديث معاملات → تكرار. لا تعرض الأوزان كمكتبة نصوص أو كنسخ محفوظة من الوثائق. عدد المعاملات لا يثبت جودة أو موثوقية. |
| S12 | معتمد | يجب تثبيت الفروق: التدريب = تعلم واسع من بيانات؛ الضبط الدقيق = تدريب إضافي موجّه؛ الأمر = تعليمات وقت الاستخدام؛ RAG = استرجاع مادة خارجية وإدراجها في السياق. لا تسمِّ إدخال ملف «تدريبًا». |
| S13–S14 | معتمد بضوابط | نافذة السياق سعة للمدخلات ذات الصلة أثناء الطلب؛ سعتها وحدها لا تضمن جودة الاستخدام. المخرج المحتمل لا يساوي صحيحًا؛ في المثال القانوني تُضاف علامة «تحقق من المصدر الأولي». |
| S15–S18 | معتمد | هندسة الأوامر تحسين لبنية التعليمات والتكليف، وليست ضمانًا لصحة النتيجة. «هدف + سياق + مهمة + قيود + مخرج + معيار جودة» قالب عملي، لا معيار وحيد أو قاعدة تقنية للمنصات كافة. |
| S19–S21 | معتمد بضوابط | تحديد الدور يوجّه زاوية الإجابة ولا يمنح النموذج خبرة مهنية أو سلطة قانونية. الأمثلة القليلة قد تثبّت نمطًا؛ يجب أن تكون ممثلة وغير متناقضة، ولا تغني عن التحقق. |
| S22–S24 | معتمد | تفكيك المهمة يجعل المراجعة أوضح، لكنه قد يزيد كلفة التنسيق أو يضاعف الخطأ إن كانت المراحل غير مضبوطة. في الورشة، الولاية القضائية والمصادر والتاريخ والغاية عناصر سياقية تستلزم إدخالًا صحيحًا من المحاضر. |
| S25–S28 | معتمد | السياق ليس نصًا أطول؛ هو مادة ملائمة ومحدّثة ومنظمة. «الأكثر ليس الأفضل» يشرح إدارة الضوضاء، من دون ادعاء رقم أمثل لعدد الوثائق. نتيجة جيدة لا تثبت أن السياق صحيح. |
| S29–S34 | معتمد بضوابط | عرّف RAG كمسار: سؤال → استرجاع → اختيار مادة ملائمة → سياق → توليد. لا تقل إن RAG «يمنع الهلوسة». فرّق بين الذاكرة وحالة العمل ونتائج الأدوات. كل مصدر قانوني أو تاريخي في حزمة السياق يحتاج تحققًا من أصله وتاريخه وصلاحيته. |
| S35–S38 | معتمد | سير العمل سلسلة أو رسم قرار من مدخلات وخطوات ومخرجات وحالات. «تسلسلي/متوازٍ/متفرع» أنماط تصميم لا مراتب أفضلية؛ اختيارها تابع لطبيعة المهمة ومخاطرها. |
| S39–S44 | معتمد بضوابط | بوابة الموافقة البشرية قرار تصميمي لا مجرد زر؛ حدّد من يوافق وعلى أي دليل وماذا يحدث عند الرفض. استخدام الأدوات لا يعني صحة ناتجها. البيانات المنظمة تسهّل المراجعة لكنها لا تحل محلها. التحقق مستقل عن الإنشاء ويجب ألا يوصف بأنه ضمان مطلق. |
| S45–S48 | معتمد | المحادثة الذكية تجيب، وسير العمل ينفذ خطوات محددة، والوكيل قد يلاحظ ويختار أفعالًا تالية نحو هدف. هذه فروق عملية للتعليم وليست تصنيفًا قانونيًا أو معيارًا موحدًا. `Observation` هي ملاحظة ناتج/حالة قابلة للاستخدام، لا إدراك واعٍ. |
| S49–S54 | معتمد بضوابط | مستويات الاستقلالية مقياس تدريبي داخلي لا معيار دولي. طبّق أقل صلاحية لازمة، ولا تمنح النشر أو الحذف أو الاتصال الخارجي بغير موافقة صريحة عند المثال. لا تخلط بين «سجل التدقيق» وبين إثبات قانوني مكتمل؛ هو أثر تشغيلي يحتاج سلامة وحوكمة حفظ. |
| S55–S60 | معتمد بضوابط | الحوكمة طبقة عابرة للمراحل. عبارة «فوّض التنفيذ، لا المسؤولية» رسالة مهنية عن الرقابة، لا تقرير موحّد للمسؤولية القانونية؛ تختلف المسؤوليات باختلاف الاختصاص والعقد والتنظيم والواقعة. |

## قواعد أمثلة المهنة والقانون

- لا تُنسب قاعدة أو حكم أو مادة نظامية من دون مرجع أصلي وتاريخ تحقق.
- لا يُستخدم ملف عقد أو نزاع حقيقي أو بيانات شخصية في العرض؛ الأمثلة تُجرّد أو تُصطنع تعليميًا.
- عند عرض بحث قانوني: يميَّز بين **العثور على مادة** و**التحقق من حجيتها وصلاحيتها وانطباقها**.
- عند عرض تصنيف أو استخراج: تُذكر احتمالية الخطأ وحدود البيانات، ويكون المراجع البشري مسؤولًا عن الاعتماد.
