# CLAUDE.md — Project Operating Instructions

You are working inside an existing project titled:

# من مخاطبة الآلة إلى تفويضها
## من هندسة الأوامر إلى هندسة الوكلاء
**From Prompt Engineering to Agent Engineering**

This is not a traditional PowerPoint deck. It is an **Interactive Cinematic Web Presentation** for a practical lecture of about three hours, delivered from the browser and published through GitHub Pages.

Repository: `from-prompt-to-agent`.

---

## 1. Non-negotiable rule

Do **not** restart the project from scratch.

Always follow:

**Inspect → Understand → Preserve → Improve → Test**

Before changing anything:

1. Inspect the current repository structure.
2. Read the existing React, TypeScript, SCSS/Sass, components, data, public assets, and generated `site/` output.
3. Identify what already works.
4. Preserve valid existing work.
5. Improve only what needs improvement.
6. Do not replace the identity, structure, or scene system without a clear reason.
7. Do not delete working scenes, components, or interactions merely to create an alternative.

## 2. Core idea

The lecture tells the journey from merely addressing the machine to delegating work to it:

**فهم الآلة → هندسة الأوامر → هندسة السياق → تصميم سير العمل → هندسة الوكلاء → الرقابة على التفويض**

The central message:

> We are not only teaching users how to write better prompts; we are teaching them how to design AI-based work systems while preserving human oversight.

This idea must remain visible in the content, visuals, navigation, animation, and interaction model.

---

## 3. Target audience

The lecture is not for programmers only.

The primary audience is:

**Professionals, researchers, academics, lawyers, consultants, trainers, administrators, and knowledge workers who use AI tools and want to move from using ChatGPT to designing professional AI workflows and agent-based systems.**

Assume no programming background. However, the lecture must move beyond introductory use and gradually reach advanced concepts:

**Prompt Engineering → Context Engineering → AI Workflows → Agent Engineering → Human Oversight**

Use professional, legal, research, educational, administrative, and business examples. Do not rely only on software-development examples.

## 11. Motion rule

Animation must be **functional**, not decorative.

Every motion should explain an idea.

Examples:

- Context Window: information enters the window, fills it, and old items leave as the window reaches capacity.
- RAG: the question moves to the model, then to a knowledge base, then retrieved information returns before answer generation.
- Agent: the loop shows goal, reasoning, tool use, observation, decision, and action.
- Workflow: a single task decomposes into connected stages.
- Tokens: text breaks into smaller units and then representations.

Avoid movement that only makes the screen busy.

Preserve reusable architecture:

## 16. Performance and accessibility

- Prioritize 16:9 desktop presentation mode.
- Keep animation smooth.
- Respect `prefers-reduced-motion`.
- Preserve keyboard navigation.
- Maintain high contrast.
- Avoid depending on color alone to communicate meaning.
- Keep typography readable on a large projected screen.

---

## 17. Evaluation checklist

For every scene, ask:

1. What idea does this scene teach?
2. What does the audience see first?
3. What happens on the first click?
4. Does the motion clarify the concept?
5. Can it be understood from a distance?
6. Are there unnecessary elements?
7. Does the presenter need control within the scene?
8. Can the scene be replayed or revisited?
9. Does it connect logically to the previous and next scenes?
10. Does it support the central journey from Prompt to Context to Workflow to Agent?
